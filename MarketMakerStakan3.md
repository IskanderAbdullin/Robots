# Контекст: торговый робот MarketMakerStakan3 для OsEngine

## 1. Общая информация
- **Проект:** OsEngine (C#), путь `R:\1.OSENGINE\04.10.2026\OsEngine-master`.
- **Работаем только с файлом** `project/OsEngine/bin/Debug/Custom/Robots/MarketMakerStakan3.cs`. Роботы из `Custom\Robots` компилируются OsEngine при запуске (Roslyn), dotnet build их НЕ компилирует — проверяет только синтаксис, если файл в проекте (этот не входит).
- **ВАЖНО:** OsEngine обновляется через `Engine\Updater\Builds\Build_*` — запуск может идти из снапшота со СТАРОЙ копией Custom\Robots. После правок робота проверять, что запущен свежий экземпляр.
- Не пиши комментарии в коде вообще, фиксируй итог здесь кратко.
- В папке project изучи AGENTS, CONTEXT, CONTEXT_CODING_GUIDELINES, CONTEXT_ROBOTS_ARCHITECTURE, CONTEXT_HIGH_FREQUENCY при необходимости.

## 2. Базовые классы и API
- Наследуется от BotPanel, BotTabSimple через TabCreate(BotTabType.Simple).
- Стакан: `_tab.MarketDepthUpdateEvent`, работаем с копией `marketDepth.GetCopy()`. Bids/Asks — списки MarketDepthLevel, лучший уровень — индекс 0.
- Заявки: `_tab.BuyAtLimit / SellAtLimit` (каждая = позиция). Снятие: `_tab.CloseOrder(order)`. Перестановка: `_tab.ChangeOrderPrice` — только если `_tab.ServerIsSupportChangeOrderPrice` или `_tab.EmulatorIsOn`.
- Округление: `_tab.Security.PriceStep/VolumeStep`, цены через `_tab.RoundPrice`.
- Портфель: `_tab.Portfolio.ValueCurrent`; свободные деньги — GetPositionOnBoard() с SecurityNameCode "rub". У T-Invest список позиций может быть пуст — готовность портфеля надёжнее проверять по ValueCurrent > 0.
- Ручное сопровождение отключено: `DisableManualSupport()` + OrderTypeTime = GTC.
- Позиции журнала грузятся из `Engine\<Вкладка>DealController.txt` при старте — робот их игнорирует (чистый старт, см. п.5).

## 3. Обработка тиков
- Throttling: в IsOsTrader обработка не чаще 10 раз/сек (100 мс). В тестере без ограничения. В IsOsOptimizer — сразу выход. Режим Off не троттлится.
- Вся работа под `_planLock`; OrderUpdateHandler чистит словари под тем же lock.

## 4. Параметры робота
- Режим (Off/On); режим покупки («Один уровень (макс. объём)» / «Распределение сверху вниз» / «Перед большой заявкой»); суммарный объём покупки; % от объёма уровня; режим объёма продажи («% от бумаг в портфеле» / «% от всего портфеля»); % продажи; режим объёма покупки («Фиксированный» / «% от стоимости портфеля» / «Максимум без маржи»); мин. объём стены (умолч. 100000); превышение над медианой (умолч. 3); проверка моргания N тиков (умолч. 3) — анти-спуфинг стены И окно сглаживания бюджета продажи.

## 5. Действующая логика

### Покупка
- «Один уровень»: одна заявка на бид-уровне с макс. чужим объёмом (GetForeignVolumes).
- «Перед большой заявкой»: одна заявка на 1 PriceStep выше первой стены (чужой объём >= мин. стены И >= множитель × медиана). Анти-спуфинг: стена должна подтвердиться N тиков подряд на одной цене. Цена стены + PriceStep >= лучший аск — не ставим.
- «Распределение сверху вниз»: от лучшего бида вниз, объём = min(%/100 × чужой объём уровня, остаток), округление вниз до VolumeStep, 0 — пропуск.

### Продажа
- Всегда распределением от лучшего аска вверх по той же формуле.
- Бюджет плана (GetSellPlanVolume, режим «% от бумаг») = свободные бумаги + остатки наших Sell-заявок × %/100 — план не зависит от блокировки бумаг своими заявками.
- **НЕ УБИРАТЬ:** свободные бумаги = PositionOnBoard.ValueCurrent − ValueBlocked (двойной счёт ValueBlocked в T-Invest, баг 0.3).
- Бюджет плана ограничен `_sellPapersBase` = минимум GetSellPlanVolume за последние N тиков (`rest = _sellPapersBase`) — гасит ложный рост бюджета при лаге ValueBlocked у брокера. Рост бюджета входит в план только продержавшись N тиков.
- Гистерезис по чужому объёму: `_sellForeignBasis` (цена → мин. чужой объём с последней смены базы) — рост чужого объёма план не увеличивает.

### Окно успокоения (баг 12)
- После любых своих действий с заявками (place/cancel/changePrice) штампуется `_lastOwnOrdersChange`; в течение OwnOrdersSettleTime = **0,4 сек** ApplyStandingOrdersFloor подпирает план на ценах стоящих заявок их остатком (только поднимает объём на совпадающих ценах, новые цены не добавляет). Гасит гонку: позиции/портфель обновляются раньше, чем стакан показывает наши заявки → GetForeignVolumes дважды вычитает нас → ложное съёживание плана → cancel/place, заблокированный клэмпом.

### Чистый старт
- Позиции, восстановленные журналом на момент создания робота, игнорируются логикой (`_restoredPositionNumbers`, фильтр в GetMyActiveOrders) — робот не усыновляет старые заявки и не снимает их в Off. Внимание: реально висящие на бирже заявки прошлой сессии продолжают блокировать бумаги/деньги.

### Таймер старта
- Первый тик On: лог «Робот включён в режим "On"», штамп `_onTime`. Один раз при готовности портфеля: «Портфель получен через X сек после включения». Готовность = Portfolio != null и (ValueCurrent > 0 или непустые позиции).

## 6. Сверка плана с заявками
- План строится каждый обработанный тик; активные заявки — из _tab.PositionsAll → OpenOrders (Active/Partial, плюс Pending/None у Opening), один раз за тик.
- Быстрый выход: OrdersMatchPlan (мультимножество + допуск VolumesMatch).
- **VolumesMatch:** Sell — рост плана = несовпадение сразу, снижение — совпадение пока план ≥ стоящий − max(VolumeStep, 10% стоящего). Buy — совпадение пока стоящий ≥ план − max(VolumeStep, 20% плана).
- Перестановка одной заявки через ChangeOrderPrice (очередь сохраняется); повторный запрос на ту же цену — не чаще 60 сек (_ordersOnPriceChange).
- ApplyPlanSide: префикс 0..k−1 не трогаем; с k-й — снимаем всё и проставляем план (замена занимает два тика). Бюджетный клэмп: reserved = остатки всех активных заявок стороны (включая снимаемые), canPlace = бюджет − reserved.
- Повторный отзыв той же заявки — не чаще 60 сек (_ordersOnCancel).

## 7. Особенности ядра (не правим, работаем только с роботом)
- «Сделка не открылась ... OpeningFail» — штатный лог ядра (BotTabSimple.cs:7926): отзыв неисполненной открывающей заявки = OpeningFail позиции, по сообщению на позицию. Возникает и при снятии заявок в Off.
- Портфель от сервера приходит быстро (замерено 0,0 сек от On); основная пауза до первых заявок — сам запуск робота OsEngine после нажатия On (~5-8 сек), вне компетенции робота.
