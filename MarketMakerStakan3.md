## 2. Базовые классы и API
- Наследуется от BotPanel (namespace OsEngine.OsTrader.Panels).
- Использует BotTabSimple (одна вкладка, один инструмент) через TabCreate(BotTabType.Simple).
- Стакан: событие _tab.MarketDepthUpdateEvent (тип Action<MarketDepth>).
  - MarketDepth.Bids / MarketDepth.Asks — списки MarketDepthLevel (лучший уровень — индекс 0).
  - MarketDepthLevel.Price, .Ask, .Bid (объёмы).
- Заявки: _tab.BuyAtLimit(volume, price) / _tab.SellAtLimit(volume, price) возвращают Position.
  - Каждая заявка — открывающая заявка позиции (в OsEngine нет публичного способа выставить заявку без позиции).
  - Снятие: _tab.CloseOrder(order) (безопасное снятие с проверкой состояния).
- События заявок: _tab.OrderUpdateEvent (Action<Order>).
- Округление: _tab.Security.PriceStep, VolumeStep, Decimals, DecimalsVolume.
- Портфель: Portfolio.ValueCurrent (полная стоимость портфеля, включая заблокированные деньги и бумаги). Для T-Инвеста это TotalAmountPortfolio.
- Доступные деньги: Portfolio.GetPositionOnBoard() с SecurityNameCode = "rub", поле ValueCurrent.

## 3. Важное исправление: отключение «Сопровождения позиций»
По умолчанию OsEngine имеет встроенный механизм BotManualControl, который через 50 секунд отзывает любые «висящие» открывающие/закрывающие заявки (см. BotManualControl.cs:96-109). Это ломало логику маркетмейкера.

В конструкторе робота (после TabCreate) эти настройки принудительно отключаются:

    _tab.ManualPositionSupport.SecondToOpenIsOn = false;
    _tab.ManualPositionSupport.SecondToCloseIsOn = false;
    _tab.ManualPositionSupport.SetbackToOpenIsOn = false;
    _tab.ManualPositionSupport.SetbackToCloseIsOn = false;
    _tab.ManualPositionSupport.StopIsOn = false;
    _tab.ManualPositionSupport.ProfitIsOn = false;
    _tab.ManualPositionSupport.DoubleExitIsOn = false;
    _tab.ManualPositionSupport.OrderTypeTime = OrderTypeTime.GTC;
    _tab.ManualPositionSupport.Save();

Комментарий в коде: это отключает штатный «отзыв заявок по времени» OsEngine, который конфликтует с логикой маркетмейкера.

## 4. Параметры робота
Список параметров (значения по умолчанию и диапазоны — в коде, `CreateParameter(...)`):
- Режим (Off / On)
- Режим покупки («Один уровень (макс. объём)» / «Распределение сверху вниз» / «Перед большой заявкой»)
- Суммарный объём покупки (лоты или % портфеля) — двойное назначение, см. ниже
- Процент от объёма уровня
- Режим объёма продажи («% от бумаг в портфеле» / «% от всего портфеля»)
- Процент продажи
- Режим объёма покупки («Фиксированный» / «% от стоимости портфеля» / «Максимум без маржи»)
- Мин. объём стены (decimal, по умолчанию 100000) — только для режима «Перед большой заявкой»
- Превышение над медианой, раз (decimal, по умолчанию 3)

Двойное назначение поля «Суммарный объём покупки»:
- В режиме «Фиксированный» — объём в лотах.
- В режиме «% от стоимости портфеля» — процент от полной стоимости портфеля.

## 5. Логика выставления заявок

### Покупка
- Режим «Один уровень»: одна заявка на бид-уровне с максимальным суммарным чужим объёмом. Объём = значение поля «Суммарный объём покупки» (если режим «Фиксированный»).
- Режим «Перед большой заявкой» (BuildWallBuyPlan / FindWallPrice / MedianVolumes): одна заявка на покупку на 1 PriceStep ВЫШЕ первого уровня-«стены». Стена = первый уровень Bids (объёмы через GetForeignVolumes), чей объём >= «Мин. объём стены» И >= «Превышение над медианой» × медиана объёмов всех Bids. Медиана по всем уровням Bids; уровней < 2 или медиана 0 — стены нет. Если цена стены + PriceStep >= лучший аск — не ставим. Стены нет — ничего не ставим, один раз за смену состояния лог «стена не найдена» (флаг _wallNotFoundLogged). Без защиты от спуфинга и гистерезиса.
- Режим «Распределение сверху вниз»: от лучшего бида (индекс 0) вниз по уровням:
  - Объём заявки = min(Процент/100 × чужой объём уровня, остаток суммарного объёма).
  - Округление вниз до VolumeStep. Если получился 0 — уровень пропускается.
  - Остаток уменьшается на фактически взятый объём.
  - Когда остаток исчерпан — стоп. Последняя заявка может быть меньше процентного объёма уровня — это легитимно.
- Чужой объём уровня = суммарный объём из стакана минус наши собственные активные заявки на этой цене.

### Продажа
- Всегда распределением от лучшего аска (индекс 0) вверх по уровням.
- Доступно для продажи = бумаги в портфеле × % продажи (без вычитания зарезервированного — см. баг 6 в п.7).
- Объём заявки = min(Процент/100 × чужой объём уровня, остаток доступного объёма).
- Остаток доступного объёма продажи:
  - Режим «% от бумаг в портфеле»: Процент/100 × количество бумаг инструмента в портфеле.
  - Режим «% от всего портфеля»: Процент/100 × полная стоимость портфеля / цена лучшего аска.
- **Важно:** робот не смотрит на исторические позиции (шорт/лон), только на текущее количество бумаг в портфеле.

### Режимы объёма покупки
- «Фиксированный»: суммарный объём = значение поля «Суммарный объём покупки» (лоты).
- «% от стоимости портфеля»: суммарный объём = Процент (из поля) /100 × полная стоимость портфеля / цена лучшего бида. Не вычитаем зарезервированные под заявки деньги (это вызывало осцилляцию).
- «Максимум без маржи»: суммарный объём = (свободные деньги − зарезервированные под наши buy-заявки) / цена лучшего бида. Плечо не учитывается (OsEngine не знает размер плеча).

## 6. Сверка плана с реальными заявками
- На каждом тике стакана строится план заявок (список: сторона, цена, объём).
- Реальные активные заявки собираются из _tab.PositionsAll → OpenOrders, где State == Active || Partial и позиция не в OpeningFail/Done.
- Сравнение OrdersMatchPlan: мультимножественное сравнение с допуском VolumesMatch:
  - объёмы считаются совпавшими, если |план − реальный| ≤ max(0.5 × VolumeStep, 1% от планового).
- Если план совпадает с реальными заявками — ничего не делаем (защита от дёрганья).
- Если не совпадает — снимаем лишние, выставляем недостающие.
- Перед снятием проверяем Order.State: снимаем только Active / Partial / Pending. Для Cancel / Fail / Done — пропускаем.
- Ведётся список _ordersOnCancel (по NumberUser), чтобы не слать повторный отзыв до подтверждения сервером.

## 7. Известные баги и их исправления (история)
1. Отзыв заявок через 50 секунд — отключено BotManualControl (см. п.3).
2. Ошибка «The order has been cancelled or rejected» — возникала из-за повторного снятия уже мёртвой заявки. Исправлено проверкой состояния и списком _ordersOnCancel.
3. Осцилляция объёма в режиме «% от стоимости портфеля» — план считался от свободных денег с вычетом зарезервированного. Исправлено: теперь берётся полная стоимость портфеля (ValueCurrent) без вычитания.
4. Хаос в распределении при исчерпании суммы — из-за округления с принудительным минимумом «1 лот» и слишком строгой сверки объёмов. Исправлено: RoundVolumeDown (может вернуть 0, уровень пропускается) и допуск VolumesMatch.
5. **Робот не выставлял заявки после смены инструмента** — старые шорт-позиции по другому инструменту попадали в PositionsOpenAll, GetNetPositionVolume возвращал отрицательное значение, и робот пропускал продажи. Исправлено: убрана проверка шорта, теперь доступный объём продажи = бумаги в портфеле × % − зарезервировано под активные sell-заявки. Робот смотрит только на текущее количество бумаг, не на историю позиций.
6. **Продажа: ставит заявку и тут же снимает («не совпала с планом»), бесконечный цикл** — план строился только на остаток бюджета (бумаги × % − зарезервировано под активные sell-заявки), т.е. описывал только НОВЫЕ заявки. Но ApplyPlan сверяет план со ВСЕМИ активными заявками: стоящая заявка не входила в план → снималась → резерв 0 → план полный → ставилась заново. Исправлено: BuildSellPlan теперь строит план от полного доступного объёма портфеля (rest = totalSellVolume), план описывает итоговое желаемое состояние, стоящие заявки покрываются сверкой. Аналогично убрано вычитание GetReservedBuyMoney в режиме покупки «Максимум без маржи». Методы GetReservedSellVolume / GetReservedBuyMoney удалены как неиспользуемые.
